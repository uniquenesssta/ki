# 因果与信息铺垫

## 用户明确要求 · 2026-10-23

小说不能凭空冒出一件事，就直接写它的效果。要有必要介绍和前因后果，让读者先知道眼前是什么、为什么在这里，再跟人物经历变化。不能每次依赖用户指出断点。

这条要求适用于本仓库两部作品的构思、创作、续写和修改，不只是第一章或某个代词的修补。

## 因果必须从最初的事件起点建立

不能从“某件东西已经在主角身上”起笔，再把后面的使用过程写完整，就认为因果完整。

例如《军团》此前被用户指出的缺口：
- 已补：掌心有金属片 → 接触旧机械发热 → 感知故障 → 尝试控制、穿甲。
- 当时仍缺：许衡最初在哪里遇见这枚金属片？当时做了什么？它怎样进入掌心？与穿越是怎样发生联系的？
- “穿越后发现掌心已经嵌入金属片”只是宣布结果，不是交代获得经过。不能把2、3、4写顺，就遗漏1。

这里保留的是错误案例，不是固定的获得剧情模板。后续授权修改已在第一章补写从地球旧机件接触、嵌入到穿越的可见经过，仍待用户评价；不能因有了记录便默认正文一定执行合格。

## 落在正文里的做法

1. 新人物、物件、能力或冲突进入故事时，先给足理解当前事情所需的介绍。人物为何到场、物件怎样落到他手里、事情怎样开始，不能只存在于设定笔记中。
2. 人物作出判断或使用能力之前，要有他实际经历、观察、获知或尝试的依据。不得作者知道，人物就突然知道。
3. 关键变化写清触发与结果。得到物件、首次激活、打开新区域、获得奖励，都不能靠“忽然出现”代替发生过程。
4. 对象离开叙述中心多段后再出现，重新点明名称；不让“这东西”“它”紧接另一个物件，迫使读者猜。
5. 必要因果可以简洁地交代，也可以通过场景写出，不等于每一步琐事都展开。不能以“文笔干净”“推进快”为理由删掉最关键的起因。

可以保留尚未知晓的深层秘密，但必须与漏写发生经过区分：核心为何被制造可以暂未揭晓，主角如何遇到它、如何被它影响，却不能只用一句“已经在掌心”跳过。也不必先列完全部世界等级；应先给读者理解眼前强弱与得失的参照。

## 动笔前与交稿前实际检查

- 找出本次最重要的事件或能力，向前追问：它最初是怎么开始的？这个起点在正文哪一处？
- 首次接触、人物行动、触发变化、观察结果、后续选择之间，是否缺了一环？若缺，只补后半截仍不算修好。
- 将自己当作没有读过设定和聊天记录的读者：此时能否知道“是什么、从哪来、谁知道、为何这样做”？
- 找出突然出现的物件、熟练用出的能力、无来源的情报与无触发的奖励，逐项回到原文确认，不用“后面会解释”敷衍当前无法理解的因果。
- 发现缺口先修改，再交稿。记录了规则不代表执行过检查，更不能宣布文本必然合格。

这是一条阅读质量要求，不是固定章序或逐段填表。保持创作空间，但不能把缺少前因误当成留白。
